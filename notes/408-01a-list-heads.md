# 微课 01 补充：头指针、头结点与链表形态

日期：2026-10-27。用户问题：“链表有几种 header 的形式？这是常见的形态么？”

本课中的带头结点单链表是一种常见表示。这里的 header/head 不能单凭名字判断含义，要看它指向什么，以及题目对结点的约定。用户本次是概念追问，不是 LL-01 的答案，也不能据此断定已掌握或完全不会。

## 头指针和头结点不是同一事物

- 头指针：保存链表入口地址的指针变量，例如 `Node *head`。
- 头结点：放在第一个数据结点之前的额外结点，也常称哑结点或哨兵结点；它不代表一个有效数据元素。数据域可不用，也可按实现约定保存附加信息。
- 首元结点：第一个真正保存有效数据元素的结点；空表没有首元结点。

下图中 `head` 是指针变量，方括号表示实际结点；`H` 是额外头结点，数字是数据元素。

## 按有无头结点，先掌握两种

不带头结点：

```text
head → [1] → [2] → [3] → NULL
```

head 直接指向首元结点。空表时 `head == NULL`；遍历从 `p = head` 开始。

带头结点（当前题目采用的形式）：

```text
head → [H] → [1] → [2] → [3] → NULL
```

head 指向额外的 H，`head->next` 指向首元结点。有效、已初始化的空表为 `head → [H] → NULL`，判空为 `head->next == NULL`；遍历数据结点从 `p = head->next` 开始。

这里假定 head 指向已存在的 H；`head == NULL` 表示没有可用头结点，不能直接求 `head->next`。

| 非循环单链表的操作 | 不带头结点 | 带头结点 |
|---|---|---|
| 第一个数据结点 | head | head->next |
| 空表条件 | head == NULL | head->next == NULL（head 有效） |
| 开始反转的位置 | cur = head | cur = head->next |
| 反转后连接入口 | 更新调用方的 head | head 保持指向 H，修改 head->next |

## 为什么额外加 H

以在某个结点 p 后插入新结点 s 为例：

```c
s->next = p->next;
p->next = s;
```

带头结点时，在表头插入也可以令 `p = head` 使用同一逻辑，因为首元结点之前有 H。空表也能用这两句。在适用的插入/删除操作中，这减少了对第一个数据结点的特殊处理；不代表所有链表操作都无需判空或检查边界。

不带头结点时，表头插入需要更新入口：`s->next = head; head = s;`。若在 C 函数中修改调用方的 head，可返回新指针由调用方接收，或传入 `Node **`；仅修改值传递的 `Node *head` 形参不会改变调用方变量。带头结点的版本可通过 `Node *head` 修改实际 H 的 next 字段。

## 单双向、是否循环是另外的分类维度

有无头结点不等同于单双向，也不等同于是否循环。以单链表为例：

| 形态 | 尾结点 next | 空表表示（本表约定） |
|---|---|---|
| 不带头结点，非循环 | NULL | head == NULL |
| 带头结点，非循环 | NULL | head->next == NULL |
| 不带头结点，循环 | 指回第一个数据结点，即 head | head == NULL |
| 带头结点，循环 | 指回头结点 H，即 head | head->next == head |

双向链表再为结点增加 prev 前驱链接。不同实现还可能使用首尾两个哨兵，或由包含 head、tail、size 的管理结构保存链表信息；管理结构也可能被叫作 header，它与一个额外头结点不是同一概念。

因此没有脱离分类标准的唯一“header 一共几种”。当前先区分两种头部表示，其他维度按题目识别即可。循环表的结束条件不同，不能直接套用遇到 NULL 停止的反转代码。
