## Cache 解决什么问题

CPU 执行计算很快，访问主存（内存）相对较慢。Cache 是容量较小、访问较快的硬件缓存，保存主存中一部分数据的副本，帮助减少 CPU 等待取数的时间。

先用只有一层 Cache 的简化读访问模型理解：

```text
CPU 要读数据
    ↓
检查 Cache
    ├─ 找到对应有效数据：命中，从 Cache 读取
    └─ 没找到：未命中，从主存调入所在块，再取得数据
```

本轮只讲读取，不展开多级缓存、写策略和地址映射。

## 一次通常搬一块，而非只搬一个变量

CPU 可能只需要一个整数，但 Cache 未命中时，通常把包含它的一整块连续数据调入。

例子条件：

- `int A[16]` 连续存储，每个 int 占 4 B；B 表示字节。
- 每个块为 32 B，A[0] 位于一个块的起点，即数组首地址按块对齐。
- Cache 初始为空；只考虑这里列出的读取，无预取、无其他访问，已调入块在本轮访问中不被替换或失效。

每块容纳 `32 ÷ 4 = 8` 个整数。数组在主存中的两个块为：

```text
第一个块，32 B：[A[0] A[1] A[2] A[3] A[4] A[5] A[6] A[7]]
第二个块，32 B：[A[8] A[9] A[10] A[11] A[12] A[13] A[14] A[15]]
```

先读 A[0]：Cache 为空，未命中；调入整个第一个块，因此 A[0] 至 A[7] 的数据都进入 Cache。

紧接着读 A[1]：它已随同一个块调入，所以命中，不需要再次去主存调入该块。

为什么这样做：程序访问一个位置后，经常接着访问附近位置，例如按顺序读取数组。这种倾向叫空间局部性，整块调入可以让附近的后续访问受益。
